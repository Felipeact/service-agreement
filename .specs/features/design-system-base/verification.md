## Findings

No finding fails a check. Ranked gaps in level, sampling and precision:

1. **Precision gap, C33 vs AC 33.** AC 33 says every hex value *DESIGN.md lists* SHALL equal the matching token. The proof only checks the other direction: each token hex appears somewhere in DESIGN.md, plus no `#6b7280`. A stale or extra hex in DESIGN.md would still pass. I ran the reverse direction myself and every DESIGN.md hex is present in `web/app/globals.css:8-25`, so the claim holds at HEAD, but the proof as written could not catch a drifted value.
2. **Sampling gap, C16 vs AC 16.** AC 16 covers "any button, input or nav link". The keyboard half is proven on the search input and the Pipeline nav link only; no button was tab-focused and measured. The ring comes from one global rule (`web/app/globals.css:51-53`), so a button regression would need a per-element `outline-none` override. That is low risk but not proven.
3. **Level gap, C17 vs AC 17.** AC 17 is a Button component contract ("SHALL not invoke its click handler"). The only disabled Button instance (`web/components/kanban/pipeline-view.tsx:53`) has no `onClick`, so the "handler not invoked" half cannot fail. What is actually proven is the native `disabled` attribute (`web/components/ui/button.tsx:21` spreads props onto `<button>`), which is what guarantees the behaviour.
4. **Precision gap, checks.md Coverage note.** The note says "C22 and C25 compute totals in the proof with `Intl.NumberFormat`, independent of `formatCad`". C25 compares against the literal `$0/yr` and uses no Intl. C22 re-implements essentially the same Intl call as `web/lib/money.ts:4-9`, so it is not independent of the formatter's algorithm (en-CA / CAD / fraction digits). C5 is the real guard on the formatter.
5. **Sampling gap, viewport boundaries.** Mobile is sampled at 375 only and tablet at 768 only. 1024 is covered by C9, but 1023 and 767 are never exercised, so the `lg`/`md` switch points are proven only from the desktop side. C14's "header controls wrap below the title" checks the search input but not the "New agreement" button.
6. **Vacuous scope, C3.** `web/lib` holds no `.tsx` files, so the `.tsx` grep there is vacuous. `web/lib/pipeline-stage.ts` and `web/lib/sample-pipeline.ts` are `.ts`. I ran the same grep over `.ts` in `web/lib` and `web/components` with no hits. The real enforcement is `--color-*: initial` at `web/app/globals.css:6`, which makes any default-palette class render nothing.
7. **C32 review item (fictitious names), held.** `web/lib/sample-pipeline.ts:17-28`: Harbourview Towers Strata, Pinecrest Office Park, Lakeshore Brewing Co., Northgate Self Storage, Juniper Medical Clinic, Copperleaf Seniors Residence, Tidewater Hotel, Glacier Valley Cold Storage, Brookhaven Community Centre, Ridgeline Retail Plaza, Saltmarsh Bakery, Fernwood Dental. These are generic place-plus-trade compounds with no addresses, people or identifiers, and they read as fictitious. Some generic names (for example "Fernwood Dental", "Tidewater Hotel") may coincide with real small businesses somewhere, but nothing ties them to one.
8. **Console note (C35, not a failure).** `browser_console_messages` with `all: true` shows one earlier React hydration-mismatch error caused by `style={{caret-color:"transparent"}}` on the search input. That is the screenshot-capture injection from the pre-existing MCP session at 16:29, before this run. In this run the `page.on('console')` / `pageerror` listener logged 0 errors or warnings across every load, and the current-navigation listing is empty.
