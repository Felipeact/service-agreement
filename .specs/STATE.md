# Project state

## Decisions

| ID | Decision | Rationale | Status | Date |
| --- | --- | --- | --- | --- |
| AD-001 | Pipeline stage keys are `in_progress`, `sent`, `accepted`, `completed`, `refused`, in that order; the Phase 1 domain layer owns them and the UI imports them | a stage spans agreement and contract statuses, so it cannot reuse either enum; UI, filters and later URL params bind to these names | active | 2026-10-19 |
| AD-002 | Colours, radii and shadows are read only through the Tailwind `@theme` role tokens in `web/app/globals.css`; no hex literal or default-palette class in components | one source of truth, and role names let customer-facing surfaces swap in the tenant accent | active | 2026-10-19 |
| AD-003 | Every tenant table has `org_id uuid not null references orgs on delete cascade`, and every child-to-parent reference is a composite FK on `(parent_id, org_id)` against a parent `unique (id, org_id)` | a reference cannot cross orgs even when RLS is bypassed (service role, seeds); every later table copies this | active | 2026-10-19 |
| AD-004 | RLS policies call only `private.is_org_member(org)` and `private.has_org_role(org, roles[])` (security definer, `search_path = ''`, in the unexposed `private` schema), wrapped as `(select ...)` | one place decides membership; JWT claims would go stale after a role change | active | 2026-10-19 |
| AD-005 | Statuses are `text` with a `check` constraint, never Postgres enums; ids are `uuid default gen_random_uuid()`; money is `bigint` `_cents` | a check can be changed in a migration while an enum value cannot be removed; the TS state machine owns transitions | active | 2026-10-19 |
| AD-006 | Migration files are named `<version>_<name>.sql`, where `<version>` is the timestamp `apply_migration` recorded on the remote | the local history then matches the remote one, so a later `supabase db push` does not re-apply them | active | 2026-10-19 |
| AD-007 | The standard equipment catalog lives in `private.catalog_asset_types` / `private.catalog_asset_type_tasks`, filled by migration, unreadable by `anon` and `authenticated`; orgs read only their own copy in `public.asset_types` / `asset_type_tasks` | SQL onboarding (Phase 5) can read it with no app runtime, and it never shows up as a second catalog queries could hit | active | 2026-10-19 |
| AD-008 | An org gets the catalog only through `private.seed_org_catalog(org)` (security invoker, `search_path = ''`, `on conflict (org_id, code) do nothing`, tasks copied only for types that call inserted); no trigger on `orgs`. The copy is the org's own, with no FK back to the template | re-runs are no-ops and existing types keep their checklists; a trigger would break fixtures that pre-insert `RTU` and would stop onboarding from creating an empty catalog | active | 2026-10-19 |
| AD-009 | Demo data lives only in `supabase/seed.sql` (one `begin`/`commit`, fixed ids `md5('demo:<kind>:<n>')::uuid`, demo org id `00000000-0000-4000-8000-00000000de30`, every insert `on conflict do nothing`), never in a migration | a migration would plant a fictitious tenant in every future environment, production included; fixed ids make re-runs idempotent and let the auth item attach a member to a known org | active | 2026-10-19 |
| AD-010 | Pure domain code lives in `web/domain/<area>/index.ts`; `web/eslint.config.mjs` forbids `next*`, `react*`, `@supabase/*`, `@/lib`, `@/components` and `@/app` imports there, and domain sources read no clock and no randomness | ports, adapters and use cases depend on the domain, never the reverse; a lint rule makes "pure" checkable instead of a convention | active | 2026-10-23 |
| AD-011 | A transition returns `{ ok: true, status, event }` or `{ ok: false, error: { code, from, command } }`, never throws for a domain refusal; event `type` is `<entity>.<to-status>` (`agreement.sent`, `contract.completed`), `entityType` is `agreement` or `contract` | n8n W1-W4 bind to these names and `events.type` stores them; the portal shows a refusal to the customer, so it is a value the type checker sees | active | 2026-10-23 |
| AD-012 | Money in TypeScript is `Cents = number & { __brand: "Cents" }`, made only by `cents(n)` (non-negative safe integer, else `RangeError`) | a dollar amount cannot pass as cents unnoticed; PostgREST returns `bigint` as a JSON number, so `bigint` would mean converting at every boundary | active | 2026-10-23 |
| AD-013 | Unit tests use Vitest (`npm test` in `web/`), as `*.test.ts` beside the code | one runner for every later unit test; it resolves the `@/` alias | active | 2026-10-23 |
| AD-014 | Layers are `web/domain`, `web/application/{ports,use-cases}`, `web/infrastructure/<adapter>` and `web/composition` (`server-only`). ESLint forbids framework and database imports in `application/**`, UI and composition imports in `infrastructure/**`, and `@/infrastructure` / `@supabase/*` in `app/`, `components/` and `lib/` | use cases stay testable with fakes; UI reaches the database only through the per-request container, so no Supabase client reaches a client bundle | active | 2026-10-23 |
| AD-015 | Every state change goes through one `security invoker` RPC per entity, `public.apply_<entity>_transition(id, expected_status, to_status, event_type, payload) returns uuid`, `search_path = ''`: role check via `private.has_org_role`, compare-and-set on the expected status, event insert with `actor_id = auth.uid()`, outbox enqueue, all in one transaction. SQLSTATE `40001` stale, `P0002` not found, `42501` not allowed; adapters map them to `conflict`, `not_found`, `forbidden` | PostgREST has no transaction across requests; invoker keeps RLS deciding isolation (AD-004); the portal, DocuSeal webhook and expiry copy this | active | 2026-10-23 |
| AD-016 | `private.enqueue_outbox(event_id)` (security definer, `search_path = ''`, member check) is the only writer of `outbox`; `outbox` privileges stay revoked from `anon` and `authenticated`, and no trigger on `events` enqueues | non-transition events (`agreement.viewed`) must not reach n8n, and no user token can enqueue an arbitrary email | active | 2026-10-23 |
| AD-017 | `events.payload` is `{ "from", "to" }` plus the domain `data` keys (`reason`, `versionNo`), camelCase | n8n W1-W4 read these keys; `type` and `entity_type` already have columns | active | 2026-10-23 |
| AD-018 | Session refresh lives in `web/proxy.ts` -> `updateSession` (`web/infrastructure/supabase/session.ts`), which calls `getClaims()` and copies refreshed cookies onto the response, redirects included. Public paths are exactly `/login` and `/auth/confirm`; the matcher skips `_next/static`, `_next/image`, `favicon.ico` and image files | Server Components cannot write cookies, so only the proxy can replace an expired token; every later route relies on it | active | 2026-10-23 |
| AD-019 | Auth reaches the app only through the `AuthGateway` port (`requestMagicLink`, `verifyEmailLink`, `signOut`) and `MemberDirectory.currentMember()`, which returns `signed_out`, `no_membership` or `member` (userId, email, orgId, orgName, role). An unknown email is `ok: true` | pages cannot import `@supabase/*` (AD-014), and no caller can tell whether an account exists | active | 2026-10-23 |
| AD-020 | Server-side identity is `getClaims()` `sub`, never `getSession()` (a test fails on any `getSession(` under `web/`) | `getClaims` verifies the token; a session read from cookies can be forged | active | 2026-10-23 |
| AD-021 | Before Phase 5 onboarding, a staff member exists by dashboard invite plus `supabase/seed.sql` run with `app.demo_owner_email`; no email literal is committed outside `example.com` | a real address in git history cannot be removed; inserting into `auth.users` with SQL skips GoTrue's identities | active | 2026-10-23 |
| AD-022 | Under Cache Components, the `(app)` layout has no top-level `await`: it renders `<Suspense>` around `MemberGate`, which reads `currentMember()` and redirects, shows No workspace, or renders the shell. Pages that read `searchParams` or cookies do it in a child inside `<Suspense>` | a request read outside Suspense fails `next build`; `instant = false` would opt every app page out of static-shell validation | active | 2026-10-23 |
| AD-023 | Each screen reads through one narrow port in `web/application/ports` (`PipelineReader`, `CustomerDirectory`, `SiteRegister`, `OrgSettingsStore`) returning plain view types, `null` for a missing record, throwing on unexpected errors; adapters in `web/infrastructure/supabase` use embedded selects, cap lists at 500 rows (`.limit(500)`), and pages get them only from `getContainer()` | pages cannot import `@supabase/*` (AD-014), and one wide repository would grow for callers that use none of it | active | 2026-10-24 |
| AD-024 | Staff URLs are flat with uuid ids: `/customers`, `/customers/[customerId]`, `/sites/[siteId]`, `/settings`; a site page is not nested under its customer | agreements, import jobs and a future sites list link to a site without knowing its customer | active | 2026-10-24 |
| AD-025 | `org_settings.governing_province` holds a two-letter code from `PROVINCES` in `web/domain/org-settings`; single-row writes are a Server Action, the pure `validate...` function and a store port, not an RPC | the seed already stores `BC`, the contract will print the code; one update is already atomic, and later forms copy this shape | active | 2026-10-24 |
| AD-026 | SQL tests run with `npm run test:db [recipe...]` in `web/` (`pg` dev dependency, `SUPABASE_DB_URL` = session-pooler string in `web/.env.local`, never `NEXT_PUBLIC_`). Every `supabase/tests/*.sql` file belongs to a recipe in `web/scripts/test-db/runner.mts` `RECIPES`; `SEED_BODY` = `seed.sql` without `begin;`/`commit;`; a recipe passes only when its last row is `<last file>: pass`, and one containing a `commit` is refused | the owner can run the suite without an agent, and a test file nobody wired in fails the command instead of never running | active | 2026-10-26 |
| AD-027 | `getContainer()` calls `await connection()` (from `next/server`) before `cookies()` and before any Supabase call | the Supabase client reads the clock (token expiry); under Cache Components and Partial Prefetching that read must happen at request time, or every `(app)` page logs a blocking-prerender-current-time error | active | 2026-10-26 |
